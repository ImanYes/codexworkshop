## Требования (собраны с прошлого раза; сверь с источниками)

**Запуск:** `./main n r s [filename]`
- `n` — размер матрицы;
- `r` — сколько строк и столбцов печатать;
- `s` — способ задать матрицу: `0` значит читать из файла, `1…4` — генерировать по формуле.
Файл указывается только при `s = 0`.

**Коды возврата** (по README шаблона):
- `0` — успех.
- `-1` — неверные аргументы: не то число аргументов; `n <= 0`, `r <= 0`, `r > n`; не число (`x`, `2.5`, `2abc`, переполнение int); `s` вне 0…4; `s = 0` без файла (и файл при `s != 0`).
- `-2` — не удалось выделить память.
- `-3` — ошибка файла: файла нет; файл пуст; мало чисел; мусор вместо числа; `nan`, `inf`, `1e999`.
- `-4` — матрица вырождена (метод неприменим).

**Формулы `f(s, n, i, j)`**, индексы от 1 до n:
- s=1: `n − max(i,j) + 1`;
- s=2: `max(i,j)`;
- s=3: `|i−j|`;
- s=4: `1/(i+j−1)`.

**Вывод — строго в таком порядке и без лишних строк** (никаких «Матрица A:» и прочих заголовков):
1. Исходная матрица, не больше `r × r`, каждый элемент в формате `" %10.3e"`.
2. Строка, начинающаяся с `Inverse:`, а под ней обратная матрица в том же формате.
3. Строка отчёта из PDF:
   ```c
   printf("%s : Task = %d Res1 = %e Res2 = %e T1 = %.2f T2 = %.2f S = %d N = %d\n",
          argv[0], task, r1, r2, t1, t2, s, n);
   ```
   Сверь формат с регулярным выражением в `autograding.json`. В прошлый раз тест требовал ровно 3 знака: `Res1 = %.3e Res2 = %.3e`.

**Числа в отчёте:**
- `r1 = ‖A·A⁻¹ − E‖₁`, `r2 = ‖A⁻¹·A − E‖₁`. Норма **столбцовая**: максимум по столбцам суммы модулей.
- При `n > 11000` обе невязки равны 0 и не считаются.
- `t1` — время только функции обращения, `t2` — время только подсчёта невязок. Мерить через `clock_gettime(CLOCK_MONOTONIC)`. Генерация матрицы в `t1` не входит.
- Если матрица вырождена, отчёт всё равно печатается: `Res1 = -1`, `Res2 = -1`, `T2 = 0`, код возврата `-4`.
  Исходная матрица при этом уже напечатана, обратная — нет.
- Обращение портит `A`. Перед невязкой восстанови её повторным чтением файла или повторной генерацией.

**Устройство программы:**
- Отдельные подпрограммы, каждая в своём файле: ввод из файла, `f(s,n,i,j)`, печать матрицы, обращение, невязка.
- Подпрограмма обращения получает `n`, `A`, массив ответа и рабочие массивы только через аргументы. Глобальные переменные запрещены.
- Вся память выделяется в `main`. Всего не больше `2n² + O(n)` чисел, время `O(n³)`.
- Невязка не выделяет и не использует дополнительную память, только скалярные переменные.
- **Все переменные объявляются в начале функции,** счётчики циклов тоже: без `for (int i = …)`. Преподаватель это требует, в прошлый раз пришлось переделывать.
- Подключать только нужные заголовки. Для `abs(int)` нужен `<cstdlib>`, `<cmath>` его на старом gcc не даёт.

**Устойчивость (на этом ловили):**
- **Тест `50000 5 1` ждёт `-2` за 1 минуту.** На сервере много RAM, а Linux даёт `malloc` почти любой объём. Поэтому `malloc != NULL` ничего не гарантирует: программа начнёт считать и упадёт по таймауту (`context deadline exceeded`). Решение: если `n*n > INT_MAX`, сразу вернуть `-2`. Произведение `n*n` и индексы `i*n + j` считать в `size_t`.
- **Порог вырожденности относительный:** `eps = 1e-15 · ‖A‖`. Тогда матрица из чисел порядка 1e-100 или 1e+100 тоже обращается. Нулевую матрицу считать вырожденной.
- Проверять `isfinite` в ответе и в невязке, чтобы `inf`/`nan` не выдавались за хороший результат.
- Делить на ноль нельзя нигде.

**Стиль и проверки преподавателя:**
- `clang-format`: LLVM, `IndentWidth: 4`, `BreakBeforeBraces: Linux`, `AlignTrailingComments: false`, `AllowShortFunctionsOnASingleLine: Inline`.
  Фигурная скобка функции — на отдельной строке, у `if`/`for`/`while` — на той же через пробел. Перед `(` в вызове функции пробела нет.
- `clang-tidy` с проверками `bugprone-*, performance-*, readability-*, misc-*`, предупреждения считаются ошибками.
  Обычно он ругается на однобуквенные имена, «магические» числа (`1e-15`, `11000`, `22`), `int i, j, k;` в одной строке, функции, где легко перепутать параметры местами, и `static` вместо анонимного namespace.
- `cppcheck --enable=warning,performance`.
- `make werror`: gcc с `-Werror` и `-fsanitize=address,leak,undefined,...`.
- Флаги из лекций (тоже без единого предупреждения):
  `-pedantic -Wall -Wextra -Werror -pedantic-errors -Wpointer-arith -Wmissing-declarations -Wredundant-decls -Wcast-align -Wfloat-equal`.
- Если `clang-tidy`, `clang-format`, `cppcheck` не установлены, предложи их поставить (на Ubuntu: `sudo apt-get install -y build-essential clang-tidy clang-format cppcheck`) и запусти `.github/lint.sh`. Если запустить не получилось, прямо скажи, что lint не проверен.
- Файлы в `.github/` менять запрещено. Шаблонный `main.c` переименовать в `main.cpp` (или удалить). Компилируются все `.c`/`.cpp` в папке, так что лишних там быть не должно.

## Только для задания 22 (метод вращений через присоединённую матрицу)

«Присоединённая матрица» здесь значит расширенную `[A | E]`. Схема:
`[A | E]` → вращения → `[R | B]` → обратный ход `R·X = B` → `X = A⁻¹`.
- Вращение пары строк i, k обнуляет `a[k][i]`: `r = hypot(a_ii, a_ki)`, `c = a_ii/r`, `s = a_ki/r`. То же вращение применяется к правой части.
- Если `|a_ki| <= eps`, вращение пропускается. Если после столбца `|R_ii| <= eps`, матрица вырождена.
- Ускорения, которые не меняют ответ: у правой части на шаге (i, k) ненулевые только столбцы `0…k`. Обратный ход делать по строкам (порядок циклов i → k → j), а не по столбцам. На n=2000 это дало T1 ≈ 1.6 c вместо 4.5 c.
- Не путать с пунктом 23, где вращения идут через QR-разложение.

Для другого номера найди метод в PDF и лекции, распиши схему так же и покажи её мне до кода.

## Тесты, которые надо сделать и прогнать

Сначала прогони автотесты шаблона (`autograding.json`, бинарник `./main` из `make`). Потом свой скрипт `tests/check.py`:
- **должна отказать:**
  - каждый неверный аргумент из списка выше → `-1`;
  - `50000 5 1` → `-2` быстро;
  - нет файла, пустой файл, `1 2 / 3` (мало чисел), `1 2 / x 4`, `nan`, `inf`, `1e999` → `-3`;
  - `[[1,2],[2,4]]`, `[[1,2],[1,2]]`, `(0)`, `s=3` при `n=1`, `s=4` (Гильберт) при `n=20` → `-4` вместе с отчётом;
- **должна посчитать:**
  - `[[3,1],[4,3]]` → ровно `[[0.6,-0.2],[-0.8,0.6]]`;
  - `[[2,-1,0],[-1,2,-1],[0,-1,2]]` → первая строка `(0.75, 0.5, 0.25)`;
  - `[[0,1],[1,0]]` (ноль на диагонали — это не вырожденность);
  - `(-5)`;
  - числа порядка 1e-100 и 1e+100;
  - формулы `s=1…4` при `n=4`, сверить первые строки;
  - `n=10, r=3` печатает ровно 3×3 в нужном формате;
  - случайные 6×6 и 200×200 дают невязки `< 1e-11`, а Res1/Res2 совпадают с независимым подсчётом на Python;
- **производительность:** `n=2000`, `s=1` укладывается в минуту и с санитайзерами.

Тяжёлые тесты (n ≥ 2000, санитайзеры) запускай **по одному**, не параллельно: в прошлый раз это перегрузило память компьютера.
